The problem

Which model should run your agent?

Every model behaves a little differently. One skips a skill invocation, another uses the wrong tool, another ignores part of its input context. Today someone has to read long session transcripts by hand to find out — slow, subjective, and hard to repeat. So teams often pick a model by gut feeling, and pay more than they need to.

The answer

Write down what "good" looks like. We grade every run.

You describe once what a correct trajectory looks like: which skills to invoke, which tools to use, which input context to read, and what output to generate. The framework then reads each session transcript and compares the agent's trajectory against it, grader by grader.

ONE SIMPLE FILE

List the expected skill invocations, tool use, input context and output in one YAML file. Keep it in Git like any other code.

PROOF, NOT OPINION

Every result points to a real tool call or file change in the transcript. No AI is asked to "judge" the answer.

How it works

Four steps from a transcript to an answer.

One command, run-verify --contract <yaml> --trace-id <id>, does all four and prints the results.

01

describe

Write what a correct trajectory looks like: skill invocations, tool use, input context and output.

02

collect

Pull the session transcript from your tracing tool and tidy it into a clean, readable form.

03

grade

Each grader compares the session transcript with your list and notes every deviation.

04

report

Get a score for every grader and a report that shows where the agent went off track.

What you can do

Compare models, cut costs, fix failures.

Use the commands together for a full model comparison, or use any one of them on its own.

Good to know

What it doesn't do.

  • Not an LLM judgeScores come from what the agent actually did in the session transcript, not from another model's opinion.
  • Scores, not a yes/no verdictEach grader returns a score, so you can see how close a run came to the ideal, not just whether it slipped.
  • Needs a tracing-tool transcriptYour agent must already send its sessions to a tracing tool. This framework grades sessions; it doesn't record them.
  • Generated files are a first draftgenerate-contract builds the list from one real run. Read the match rules and adjust them before relying on it.

Quick start

Four steps to your first result.

01

Install and configure tracing tool credentials

cd wm_agents_validator
uv sync --extra dev
cp .env.example .env   # fill in your tracing tool credentials

02

Grade one agent run

uv run run-verify \
  --contract contracts/binding/binding_with_widget.yaml \
  --trace-id c4739a2868e2b7aca6430aeae2f7ea0a

03

Compare the same agent across models

uv run compare-traces \
  --contract contracts/binding/binding_with_widget.yaml \
  --trace-ids <trace-gpt4>,<trace-claude>,<trace-gemini> \
  --out comparison.html

You get one HTML file you can open anywhere: a sortable table and a colour map of how each model scored on each grader. No server needed.

04

Create a starter checklist from a real run

uv run generate-contract \
  --trace-id c4739a2868e2b7aca6430aeae2f7ea0a \
  --workflow screenshot_to_code \
  --out contracts/new_workflow.yaml
